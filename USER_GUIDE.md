## Введение

**Test Case Editor** - это приложение для создания, редактирования и управления тест-кейсами в формате JSON. Приложение предоставляет удобный интерфейс для работы с тест-кейсами, их организации в папки, редактирования и генерации отчетов.

### Основные возможности

- ✅ Создание и редактирование тест-кейсов
- ✅ Организация тест-кейсов в папки
- ✅ Управление шагами тестирования
- ✅ Прикрепление файлов к шагам
- ✅ Поиск и фильтрация тест-кейсов
- ✅ Ревью тест-кейсов с помощью LLM
- ✅ Создание тест-кейсов с помощью LLM
- ✅ Генерация Allure отчетов
- ✅ Статистика по тест-кейсам
- ✅ Импорт из Azure DevOps

## Установка и первый запуск

### Требования

- Python 3.8+ (рекомендуется 3.11+)
- PyQt5 >= 5.15.0

### Установка зависимостей

**С использованием uv (рекомендуется):**

```bash
uv sync
```

**С использованием pip:**

```bash
pip install -r requirements.txt
```

### Запуск приложения

**С использованием uv:**

```bash
uv run python run_app.py
```

**С использованием pip:**

```bash
python run_app.py
```

### Первый запуск

1. При первом запуске выберите папку с тест-кейсами:
   - Меню → **Файл** → **📁 Выбрать папку с тест-кейсами** (`Ctrl+O`)
   - Или используйте диалог выбора папки

2. Папка сохраняется в настройках для последующих запусков

3. Если папка пустая, создайте первый тест-кейс (см. раздел [Создание тест-кейса](#создание-тест-кейса))

## Работа с тест-кейсами

### Создание тест-кейса

1. **Правой кнопкой мыши** (ПКМ) на папке или корне дерева
2. Выберите **"➕ Создать тест-кейс"**
3. Новый тест-кейс создается с одним пустым шагом
4. Автоматически генерируется уникальный ID и имя файла
5. Форма редактирования открывается автоматически

### Выбор тест-кейса

- **Клик** на тест-кейсе в дереве открывает форму редактирования
- Тест-кейс выделяется в дереве

### Переименование тест-кейса

1. ПКМ на тест-кейсе
2. Выберите **"✏️ Переименовать файл"**
3. Введите новое имя (без расширения .json)
4. Нажмите **OK**

**Важно:** Имя файла не должно содержать следующих знаков: `\ / : * ? " < > |`

### Дублирование тест-кейса

1. ПКМ на тест-кейсе
2. Выберите **"📋 Дублировать"**
3. Создается копия тест-кейса с новым ID

### Удаление тест-кейса

1. ПКМ на тест-кейсе
2. Выберите **"🗑️ Удалить"**
3. Подтвердите удаление

**Внимание:** Удаление необратимо!

### Перемещение тест-кейса

**С помощью Drag & Drop:**

1. Захватите тест-кейс в дереве
2. Перетащите на целевую папку
3. Отпустите кнопку мыши

### Открытие в проводнике

1. ПКМ на тест-кейсе
2. Выберите **"🪟 Открыть в проводнике"**
3. Откроется проводник с выделенным файлом

## Редактирование тест-кейсов

### Основная информация

#### Обязательные поля

- **Название** - редактируется в заголовке формы
- **ID** - автоматически генерируется при создании

#### Основные поля

- **Автор** - автор тест-кейса
- **Владелец** - владелец тест-кейса
- **Ревьювер** - ревьювер тест-кейса
- **Статус** - выпадающий список:
  - Draft (Черновик)
  - In Progress (В работе)
  - Done (Готово)
  - Blocked (Заблокирован)
  - Deprecated (Устарел)

#### Классификация

- **Тип теста:**
  - manual (Ручной)
  - automated (Автоматизированный)

- **Test Layer:**
  - Unit
  - API
  - UI
  - E2E
  - Integration

- **Severity:**
  - BLOCKER
  - CRITICAL
  - MAJOR
  - NORMAL
  - MINOR

- **Priority:**
  - HIGHEST
  - HIGH
  - MEDIUM
  - LOW
  - LOWEST

#### Контекстная информация

- **Epic** - Epic
- **Feature** - Feature
- **Story** - Story
- **Component** - Component
- **Environment** - Окружение
- **Browser** - Браузер

#### Описательные поля

- **Теги** - многострочное поле (каждый тег с новой строки)
- **Описание** - многострочное поле с автоматической подстройкой высоты
- **Предусловия** - многострочное поле с автоматической подстройкой высоты
- **Общий ожидаемый результат** - многострочное поле с автоматической подстройкой высоты

### Сохранение изменений

1. При изменении любого поля появляется кнопка **"💾 Сохранить"**
2. Нажмите кнопку для сохранения
3. Кнопка скрывается после успешного сохранения
4. Время изменения (`updatedAt`) обновляется автоматически

## Работа со шагами

### Добавление шага

**Способы:**

1. **ПКМ на списке шагов** (в пустом месте) → **"➕ Добавить новый шаг"**
2. **ПКМ на существующем шаге** → **"⬇️ Вставить шаг ниже"**
3. **ПКМ на существующем шаге** → **"⬆️ Вставить шаг выше"**

**Особенности:**

- Автоматически прокручивается к новому шагу
- Устанавливается фокус на поле "Действие"

### Редактирование шага

**Поля:**

- **Действие** - описание действия шага
- **Ожидаемый результат** - ожидаемый результат шага

**Особенности:**

- Поля автоматически подстраивают высоту под содержимое
- Можно использовать многострочный текст

### Управление шагами

**Контекстное меню (ПКМ на шаге):**

- **"⬆️ Вставить шаг выше"** - вставить новый шаг выше текущего
- **"⬇️ Вставить шаг ниже"** - вставить новый шаг ниже текущего
- **"⇡ Переместить наверх"** - переместить шаг на одну позицию вверх
- **"⇣ Переместить вниз"** - переместить шаг на одну позицию вниз
- **"✕ Удалить"** - удалить шаг

### Прикрепление файлов к шагам

1. **Перетащите файлы** в поле шага или используйте кнопку прикрепления
2. Файлы копируются в папку `_attachment` тест-кейса
3. Имя файла формируется как `{test_case_id}_{original_name}.{ext}`
4. Файлы отображаются в панели "Файлы"

### Статусы шагов (в режиме запуска тестов)

- **✓ (зеленый)** - passed (пройден)
- **✕ (красный)** - failed (провален)
- **S (серый)** - skipped (пропущен)

**Установка статуса:**

1. Переключите режим на "Запуск тестов"
2. Нажмите соответствующую кнопку статуса у шага
3. Статус сохраняется автоматически

**Причина пропуска:**

- При выборе статуса "skipped" появится диалог выбора причины
- Можно выбрать из списка или ввести свою причину

## Управление файлами и папками

### Работа с папками

#### Создание папки

1. ПКМ на папке или корне дерева
2. Выберите **"📁 Создать папку"**
3. Введите имя папки
4. Нажмите **OK**

**Важно:** Имя папки не должно содержать следующих знаков: `\ / : * ? " < > |`

#### Переименование папки

1. ПКМ на папке
2. Выберите **"✏️ Переименовать"**
3. Введите новое имя
4. Нажмите **OK**

#### Удаление папки

1. ПКМ на папке
2. Выберите **"🗑️ Удалить папку"**
3. Подтвердите удаление

**Внимание:** Удаляется папка со всем содержимым!

#### Перемещение папки

**С помощью Drag & Drop:**

1. Захватите папку в дереве
2. Перетащите на целевую папку
3. Отпустите кнопку мыши

**Ограничения:**

- Нельзя переместить папку внутрь самой себя
- Нельзя переместить папку внутрь её подпапки

### Работа с файлами

#### Просмотр прикрепленных файлов

1. Откройте панель **"Файлы"** (правая панель)
2. Просмотрите список прикрепленных файлов
3. Для каждого файла отображается:
   - Имя файла
   - К каким шагам прикреплен

#### Открытие файла в проводнике

- **Двойной клик** на файле в панели "Файлы"
- Откроется проводник с выделенным файлом

#### Удаление файла

1. Нажмите кнопку **"×"** у файла в панели "Файлы"
2. Подтвердите удаление
3. Файл удаляется с диска и убирается из всех шагов

## Поиск и фильтрация

### Поиск по дереву

1. Введите текст в **поле поиска** в левой панели
2. Дерево автоматически фильтруется по введенному тексту
3. Поиск происходит в реальном времени
4. Очистите поле для отображения всех элементов

### Расширенная фильтрация

1. Откройте панель **"Фильтры"** (если доступна)
2. Выберите критерии фильтрации:
   - Автор
   - Владелец
   - Статус
   - Теги
   - И другие поля
3. Примените фильтры
4. Дерево обновится автоматически

## Режимы работы

### Режим редактирования (по умолчанию)

**Характеристики:**

- ✅ Все поля редактируемые
- ✅ Доступны контекстные меню для шагов
- ✅ Доступны все панели
- ✅ Можно создавать и редактировать тест-кейсы

**Переключение:**

- Переключатель в заголовке установлен в положение "Редактирование"

### Режим запуска тестов

**Характеристики:**

- ✅ Поля редактирования становятся read-only
- ✅ Контекстные меню для шагов недоступны
- ✅ Отображаются кнопки статусов шагов (passed, failed, skipped)
- ✅ Автоматически открывается панель статистики
- ✅ Можно устанавливать статусы шагов

**Переключение:**

- Переключатель в заголовке установлен в положение "Запуск тестов"

**Использование:**

1. Переключите режим на "Запуск тестов"
2. Выберите тест-кейс
3. Для каждого шага установите статус:
   - ✓ (passed) - шаг пройден
   - ✕ (failed) - шаг провален
   - S (skipped) - шаг пропущен
4. Статусы автоматически сохраняются
5. Просмотрите статистику в панели "Статистика"

## Работа с LLM

### Настройка LLM

1. Откройте **Настройки** (меню или кнопка в заголовке)
2. Перейдите в раздел **"LLM"**
3. Укажите:
   - **LLM_HOST** - адрес API (например, `http://localhost:8000`)
   - **LLM_MODEL** - модель для использования
4. Сохраните настройки

### Ревью тест-кейса

**Способ 1: Через контекстное меню**

1. Выберите тест-кейс в дереве
2. ПКМ на тест-кейсе
3. Выберите **"📝 Ревью"**
4. Откроется панель "Ревью"

**Способ 2: Через панель**

1. Откройте панель **"Ревью"** (правая панель)
2. Выберите тест-кейс в дереве

**Использование:**

1. Введите промт для ревью (или используйте сохраненный)
2. Нажмите **Enter** или кнопку отправки
3. Дождитесь ответа от LLM
4. Промт автоматически сохраняется для следующего использования

**Особенности:**

- Автоматически прикрепляется методика (если указана в настройках)
- Автоматически прикрепляется текущий тест-кейс
- История сообщений сохраняется в сессии

### Создание тест-кейсов с LLM

1. Откройте панель **"Создать ТК"** (правая панель)
2. **(Опционально)** Прикрепите файлы с техническим заданием:
   - Перетащите файлы в область прикрепления
   - Или используйте кнопку выбора файлов
3. Введите задачу для создания тест-кейсов
4. Нажмите **Enter** или кнопку отправки
5. Дождитесь ответа от LLM
6. Тест-кейсы автоматически создадутся в папке **"from LLM"**
7. Промт автоматически сохраняется для следующего использования

**Примеры промптов:**

- "Создай тест-кейсы для функции авторизации"
- "Создай тест-кейсы на основе прикрепленного ТЗ"
- "Создай позитивные и негативные тест-кейсы для API endpoint /users"

## Статистика и отчеты

### Панель статистики

**Отображение статистики:**

- **Всего тест-кейсов** - общее количество
- **Без статуса прохождения** - тест-кейсы, где все шаги пустые или pending
- **Все шаги passed** - тест-кейсы, где все шаги passed (зеленым цветом)
- **Есть failed** - тест-кейсы с хотя бы одним failed шагом (красным цветом)
- **Есть skipped** - тест-кейсы с хотя бы одним skipped шагом (серым цветом)

### Управление статусами

#### Сбросить все статусы

1. Нажмите кнопку **"Сбросить все статусы"**
2. Подтвердите действие
3. Все статусы всех шагов во всех тест-кейсах сбросятся до пустого значения

#### All PASS для текущего тест-кейса

1. Выберите тест-кейс
2. Нажмите кнопку **"All PASS"**
3. Все шаги текущего тест-кейса помечаются как "passed"

#### Сбросить статусы текущего тест-кейса

1. Выберите тест-кейс
2. Нажмите кнопку **"Сбросить статусы текущего"**
3. Все статусы шагов текущего тест-кейса сбрасываются

### Генерация Allure отчетов

1. Откройте панель **"Статистика"**
2. Нажмите кнопку **"Generate Allure"**
3. В папке приложения создастся папка `Reports/YYYY_MM_DD_HH_MM/`
4. В папке будут JSON файлы в формате Allure Test Result
5. Проводник автоматически откроется в созданной папке

**Использование с Allure:**

```bash
allure serve <путь_к_папке>
```

**Пример:**

```bash
allure serve Reports/2024_01_15_14_30
```

### Просмотр отчетов

1. Откройте панель **"Отчетность"** (правая панель)
2. Просмотрите структуру папки Reports
3. **Двойной клик** на файле/папке откроет проводник

### Генерация суммарного отчета

1. Откройте панель **"Отчетность"**
2. Нажмите кнопку **"Сгенерировать суммарный отчет"** (внизу панели)
3. Создастся суммарный отчет на основе всех отчетов

## Часто задаваемые вопросы

### Как создать первый тест-кейс?

1. Выберите папку с тест-кейсами (Файл → Выбрать папку)
2. ПКМ на корне дерева → "Создать тест-кейс"
3. Заполните форму и сохраните

### Как прикрепить файл к шагу?

1. Перетащите файл в поле шага
2. Или используйте кнопку прикрепления (если доступна)
3. Файл скопируется в папку `_attachment` тест-кейса

### Как установить статус шага?

1. Переключите режим на "Запуск тестов"
2. Нажмите соответствующую кнопку статуса у шага (✓, ✕, S)

### Как найти тест-кейс?

1. Введите текст в поле поиска в левой панели
2. Дерево автоматически фильтруется

### Как экспортировать тест-кейсы?

1. Используйте генерацию Allure отчетов
2. Или скопируйте JSON файлы вручную

### Как импортировать из Azure DevOps?

1. Меню → **Файл** → **"Импорт из ALM"**
2. Выберите JSON файл из Azure DevOps
3. Тест-кейсы создадутся в папке "from alm"

### Как использовать Git?

1. Убедитесь, что папка с тест-кейсами является git репозиторием
2. Меню → **git** → **"Выполнить commit и push…"**
3. Введите комментарий к коммиту
4. Нажмите OK

### Как изменить размер панелей?

1. Перетащите границы панелей мышью
2. Или используйте меню → **Вид** → **"Настроить ширины панелей…"**

### Почему не работает LLM?

1. Проверьте настройки LLM (LLM_HOST, LLM_MODEL)
2. Убедитесь, что API доступен
3. Проверьте подключение к сети

### Как удалить тест-кейс?

1. ПКМ на тест-кейсе → "Удалить"
2. Подтвердите удаление

**Внимание:** Удаление необратимо!

### Как переименовать файл или папку?

1. ПКМ на элементе → "Переименовать"
2. Введите новое имя
3. Нажмите OK

**Важно:** Имя не должно содержать символов: `\ / : * ? " < > |`
